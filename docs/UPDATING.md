# Обновление Dodik Tracker

В этом документе описан процесс безопасного ручного обновления self-hosted инстанса Dodik Tracker.
Процесс спроектирован так, чтобы гарантировать сохранность пользовательских данных при любых изменениях (новые таблицы, новые функции, изменение логики).

## Подготовка к обновлению

### 1. Создание бэкапа (ОБЯЗАТЕЛЬНО)
Перед любым обновлением необходимо создать резервную копию базы данных. В проекте есть скрипт, который сделает это автоматически (через docker-compose или локальный pg_dump).

Выполните в корневой директории:
```bash
chmod +x scripts/backup.sh
./scripts/backup.sh
```
Скрипт создаст файл в папке `backups/dodik_tracker_backup_YYYYMMDD_HHMMSS.sql`. Проверьте, что файл не пустой.

### 2. Получение новой версии кода
Стяните новые изменения из вашего репозитория (например, через git pull) или загрузите новые файлы в директорию проекта.

**Важно:** Никогда не удаляйте и не очищайте вашу текущую директорию с данными БД, если вы используете локальные Volume в Docker!

### 3. Проверка переменных окружения
Откройте новую версию `.env.example`. Проверьте, не появились ли там новые обязательные переменные (например, для новых API или интеграций). Если они появились — скопируйте их в ваш рабочий `.env` файл и заполните.

Убедитесь, что переменная `APP_VERSION` в `.env` соответствует новой версии, либо обновите файл `release-manifest.json`.

## Процесс обновления

### 4. Build Docker-образов (если применимо)
Соберите приложение заново.

Если вы используете Docker Compose:
```bash
docker-compose build
```
Если вы запускаете локально:
```bash
npm install
npm run build
```

### 5. Миграция Базы Данных (migrations)
Это самый важный шаг. В Dodik Tracker реализована система миграций Drizzle ORM.
**Никогда не удаляйте базу данных и не пересоздавайте таблицы вручную.**

Чтобы применить все новые изменения в схеме БД (новые столбцы, новые таблицы):

В Docker:
```bash
docker-compose run --rm app npm run db:migrate
```
Локально:
```bash
npm run db:migrate
```

Скрипт автоматически найдёт новые файлы в папке `drizzle/`, сверит их с таблицей `__drizzle_migrations` в базе данных и накатит только недостающие (ожидающие) миграции. Данные пользователей останутся нетронутыми.

Чтобы проверить статус миграций без их применения:
```bash
npm run db:status
```

### 6. Перезапуск приложения
Перезапустите сервисы, чтобы применить обновлённый код.

В Docker:
```bash
docker-compose up -d
```
Локально:
```bash
npm run start
```

## После обновления

### 7. Health Check
Убедитесь, что backend успешно подключился к БД и работает.

Откройте в браузере или через curl:
```bash
curl http://localhost:3000/api/health/ready
```
Ожидаемый ответ: `{"status":"UP","database":"connected"}`

### 8. Проверка версии в Админ-панели
Зайдите в приложение под аккаунтом администратора.
Перейдите в **Админ-панель -> Обновления**.
Проверьте, что:
- Версия приложения изменилась на новую.
- Количество ожидающих миграций (pending) равно 0.
- Статус API и Database горит зеленым (OK).
- Вы видите описание нового релиза.

## Что делать при ошибке?

Если обновление пошло не так (ошибка миграции, приложение не запускается):
1. Верните старую версию кода (git checkout, например).
2. Если миграция сломала БД, восстановите её из бэкапа:
```bash
# Пример команды восстановления
docker-compose exec -T postgres psql -U dodik_user dodik_tracker < backups/dodik_tracker_backup_ВАШ_ФАЙЛ.sql
```
3. Перезапустите контейнеры. Приложение вернётся к предыдущему стабильному состоянию.

## Пример: Добавление новой крупной фичи

Предположим, вы обновляетесь до версии 2.0.0, в которой появляется "Магазин PTS".

1. Вы делаете `./scripts/backup.sh`.
2. Скачиваете код v2.0.0.
3. Собираете: `docker-compose build`.
4. Запускаете миграции: `npm run db:migrate`. 
   В консоли вы увидите:
   ```text
   [DB Migrate] Applying migration: 0005_pts_shop_system...
   [DB Migrate] Successfully applied 0005_pts_shop_system.
   ```
5. Перезапускаете контейнеры: `docker-compose up -d`.
6. Заходите в админку, видите "Ожидающих миграций: 0", а на сайте появился раздел Магазина.

Все ваши старые пользователи, списки и достижения остались на месте, так как миграция аккуратно выполнила `CREATE TABLE pts_shop_items` и `ALTER TABLE users ADD COLUMN pts INTEGER DEFAULT 0`.
